# Замысел ZED

ZeroEffortDocs — система учёта сотрудников и связанного документооборота. Цель: убрать с стола делопроизводителя однообразную регистрацию бумаг и разрозненные папки, не заставляя жить в 1С.

## Принципы

1. **Шаблон важнее файла.** Документ — это набор полей по шаблону, а не «ещё один Word». Файл и редактор появятся, когда поля уже умеем хранить.
2. **Модули по желанию.** Компания включает то, что нужно. Кадровая база и архив старых файлов — отдельные модули, не обязательная нагрузка.
3. **Понятный экран.** Форма «приём на работу» должна выглядеть как форма, а не как конфигуратор.
4. **Один процесс — три способа жить.** Локальный браузер, сервер компании, позже окно приложения вокруг того же localhost.

## Модули

| id | Что это | Когда |
|----|---------|--------|
| `core` | Шаблоны и документы. Всегда включён. | Этап 1 |
| `employees` | База сотрудников. Документы могут ссылаться на человека. | Следующие этапы |
| `archive` | Папка старых файлов + поиск по имени и содержимому. | После кадров или параллельно, когда core стабилен |

Модуль можно включить до реализации: флаг сохранится, UI покажет «скоро».

## Как устроен документ

1. Создаётся шаблон: имя, описание, поля.
2. Поле: ключ, подпись, тип (`text`, `textarea`, `number`, `date`, `checkbox`, `select`), обязательность, варианты для списка.
3. Новый документ = выбрать шаблон, заполнить форму, сохранить.
4. Дальше (не сейчас): печать из макета, вложения, связь с сотрудником, статусы, нумерация.

Пример, ради которого всё затевалось: шаблон «Приём на работу» — ФИО, должность, дата, оклад, тип договора. Регистрация с тех пор занимает одну форму, а не копирование прошлого приказа.

## Что сознательно не делаем в этапе 1

- Редактор текста / DOCX
- Роли, логин, LDAP
- Печать и PDF
- Окно Tauri
- Полнотекст по архиву

Каркас под это есть: HTTP-сервер, SQLite, реестр модулей, шаблоны как данные. Надстройки вешаются модулями, а не переписыванием ядра.
