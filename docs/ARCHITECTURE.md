# Архитектура

## Решение по языку

Нужны были два свойства сразу: интерфейс в браузере (и локально, и на сервере) и отсутствие Electron.

- **Electron / чистый Node.** Быстрый UI, но десктоп = Chromium в каждом клиенте. Для архива и поиска это ещё и лишний рантайм.
- **Только JS-сервер.** Нормально для прототипа, хуже как «положили один `.exe` бухгалтеру».
- **Rust + Axum + SQLite + статическое UI.** Один бинарник. `cargo run` открывает браузер. `--bind 0.0.0.0:4748` — тот же код на сервере. Десктоп позже — Tauri 2 (WebView2 на Windows, не Chromium).

Поиск по архиву планируется на Tantivy. Кадровый модуль — отдельные таблицы за тем же пулом SQLite, без второй базы.

В коде крейт называется `zed`, пакет `zero-effort-docs`, бинарник `zed`.

## Процесс

```
zed.exe  →  Axum  :4748  →  браузер
                ↘ SQLite  ./data/zed.sqlite
```

UI в `web/` отдаётся из бинарника (`rust-embed`). В debug-сборке файлы читаются с диска, можно править HTML/CSS/JS без перекомпиляции.

## Данные

- `instance` — название компании на этом узле
- `modules` — включён/выключен (`employees`, `archive`)
- `templates` + `template_fields` — схема документа
- `documents` + `document_values` — экземпляр и значения полей (JSON)

Ключ поля: `^[a-z][a-z0-9_]{0,63}$`. В UI русский заголовок транслитерируется в ключ.

Значения документов keyed по ключу поля в API и по `field_id` в базе.

## Модули

Каталог модулей живёт в коде (`src/modules.rs`): id, название, описание, `available`. База хранит только флаг. Ненаписанный модуль можно включить — когда код появится, он увидит флаг.

Новый модуль: описание в каталоге, миграция таблиц, маршруты под `/api/<module>`, пункт меню если `enabled`.

## Отладка (Windows / MSVC)

Toolchain `x86_64-pc-windows-msvc` пишет PDB. LLDB (CodeLLDB, lldb-dap) это плохо ест — типичные ругань rust-analyzer/VS Code. Здесь:

- `rust-toolchain.toml` тянет `rust-src` и `rust-analyzer` — пропадают «can't find std» и «unlinked file»
- `rust-analyzer.debug.engine` = `ms-vscode.cpptools`
- launch.json: тип `cppvsdbg`, F5 собирает `zed.exe` и стартует с брейкпоинтами

Расширение C/C++ рекомендуется в `.vscode/extensions.json`. CodeLLDB наоборот listed as unwanted.
