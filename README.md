# ZeroEffortDocs (ZED)

Гибкий документооборот для компаний: шаблоны, поля, документы. Модули (кадры, архив) подключаются отдельно. Локально или на сервере — один и тот же бинарник.

Это не 1С. Схема документа задаётся формой, а не «конфигуратором».

## Сейчас (этап 1)

- Запуск локального сервера, интерфейс в браузере
- Создание шаблона документа и набор полей
- Регистрация документов по шаблону
- Реестр модулей: кадры и архив можно включить заранее, сами модули появятся следующими шагами

Текстовый редактор, печать и десктоп-обёртка — позже. Сначала каркас, который не придётся выкидывать.

## Запуск

Нужны [Rust](https://rustup.rs/) (stable) и браузер.

```bash
cargo run
```

Откроется [http://127.0.0.1:4748](http://127.0.0.1:4748). Данные пишутся в `./data/zed.sqlite`.

Полезные флаги:

```bash
zed --bind 127.0.0.1:4748
zed --bind 0.0.0.0:4748          # доступ по сети / сервер
zed --data-dir D:\zed-data
zed --no-open                    # не трогать браузер
```

Переменные окружения те же: `ZED_BIND`, `ZED_DATA_DIR`, `ZED_NO_OPEN=1`, `RUST_LOG=zed=debug`.

> На `0.0.0.0` пока нет логина. Для локальной машины это нормально. В интернет так не выставлять.

Отладка в VS Code: F5, конфигурация **ZED: запуск**. Нужно расширение [C/C++](https://marketplace.visualstudio.com/items?itemName=ms-vscode.cpptools) — у нас toolchain MSVC, PDB читает Microsoft debugger, не LLDB.

## Стек (почему так)

| Слой | Выбор | Зачем |
|------|--------|--------|
| Сервер | Rust, Axum | Один бинарник: ноутбук делопроизводителя или сервер компании |
| База | SQLite | Файл рядом с программой, бэкап = скопировать `data/` |
| UI | Браузер, без сборки | Не тащим Chromium. Позже то же UI можно обернуть в Tauri (системный WebView) |
| Модули | Флаги в базе | Кадры и архив не вшиты насильно |

Electron отклонён: тащит Chromium. Node-only отклонён: поиск по архиву и один файл на установку проще делать в Rust. Подробнее — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Замысел продукта — [docs/VISION.md](docs/VISION.md).
